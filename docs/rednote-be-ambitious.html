💡 为什么硅谷AI大佬最近突然都在说同一句话：「你还不够有野心」

最近刷AI圈，有个特别明显的感觉👇

从 Jensen Huang 黄仁勋（NVIDIA）、Alexandr Wang 汪滔（Scale AI → Meta 超级智能实验室），到 Scott Wu（Cognition / Devin）、Aaron Levie（Box CEO），再到写代码的大神 Simon Willison、Kent Beck（TDD、极限编程之父）——

这些平时八竿子打不着、分布在芯片/大厂/创业/独立开发者各个圈子的人，最近半年居然都在反复讲同一件事：

👉 「用AI别想太小了，要更有野心（be more ambitious）。」

而且我扒了一下时间线发现——这不是谁带的节奏：黄仁勋5月就在讲、Simon 9月把它写成年度主题、Rieseberg 10月才出那篇爆款框架。是一整个行业不约而同撞到了同一个点上。

· · ·

一开始我也有点反感😅 ——「又在贩卖焦虑？」

但看多了之后我发现，他们说的其实是同一个底层洞察：

🔑 The bottleneck is no longer the model.
瓶颈已经不是AI模型强不强了，而是你自己的想象力和野心。

Alexandr Wang 说得最狠：就算模型从今天起一点都不再进步，光是把现在这个水平「扩散」到全世界，就够折腾几十年了。所以未来稀缺的不是智能、不是算力，是 vision 和 ambition（愿景和野心）——AI 让你实现野心的难度直接降了 10倍甚至100倍🔥

黄仁勋的角度是给老板听的：
「You might think of productivity as cost reduction, but productivity should be thought of as raising ambition.」
——生产力不是用来裁人省钱的，是用来把目标抬高的。他在 YC 还补了一句：「不管你现在野心多大，都还不够，再 ×100。」

· · ·

那「更有野心」到底怎么落地？我觉得 Felix Rieseberg（Anthropic，带过 Claude.ai / Claude Code 桌面端） 那套框架最实用，把「野心」拆成了四个可操作的方向：

① Speed 速度：同样的事做得更快（入门款，谁都会）
② Altitude 高度：别让AI「改这一个bug」，让它「让整个App保持零崩溃」——给目标，不给任务。（他真实的例子：以前让 Claude 一个个修崩溃，后来直接说「你负责让应用别崩」）
③ Depth 深度：逼它用行业顶尖专家的工具和方法做——该上数据库和统计模型就别用 markdown 表格糊弄；关键一条👉别让模型自己给自己打分，要有独立的「裁判」
④ Range 广度：一个任务拉上多个领域的「专家」一起上（像凑一支抢劫片里的「各显神通」团队）

还有人把它往前推了一步：Addy Osmani 和 Scott Wu 都在讲 loop engineering（循环工程）——你别再亲自给AI发指令了，而是设计一个「系统」去驱动AI自己跑：定好「什么算完成」，让它循环到达标为止（Claude Code / Codex 里的 /goal）。

· · ·

Box 的 CEO Aaron Levie 还给了个超简单的自测标准👇

💬「If you could have done what you're doing before AI, you're likely not pushing it enough.」
如果这件事你没有AI也能做出来，那说明你还不够大胆——AI时代的产出应该在质上超过以前，而不只是更快。

还有个细节我特别喜欢：一个野心项目这次失败了也别删掉，过半年再试一次——因为模型一直在变强，上次做不到的，下个版本可能就成了。

· · ·

当然，也有泼冷水的，而且很诚实👇

Simon Willison 把「be more ambitious」定成了自己今年的新年目标（他说以前年年都是「少接项目、专注」，今年反着来），理由很硬核：
「The only way to find the limits of this technology is to keep pushing them until they don't work.」——不把它用到崩，你永远不知道它的边界在哪。

但他也老实承认：我的活儿反而变更难、更累了😂——因为简单的全被AI干掉了，剩给我的全是硬骨头。Kent Beck 也是又兴奋又清醒：AI让他能试「以前技术不够、根本不敢碰的项目」，但一样会撞墙、AI一样会偷懒走捷径。

所以这事儿不是鸡汤。它真正的意思是：
👉 把你的「下限」交给AI，把你的「上限」使劲往上拉。
