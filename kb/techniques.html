Getting more out of models: the four ambitions

Felix Rieseberg (Anthropic — led eng for Claude.ai, Cowork, Claude Code Desktop) frames ambition with AI as four distinct moves. Model-agnostic. (felixrieseberg.com, Oct 13)

  • Speed — the same task, faster. The economic baseline; needs little creativity.
  • Altitude — go up in abstraction: ask for the outcome, not the task. "Keep our apps crash-free," not "fix this crash." Best when you'd otherwise hold meetings about the work; this is where durable, human-out-of-the-loop workflows live (but you must first give the model the access/tools to act).
  • Depth — do the task as a field-leading expert would. Insist on real instruments (databases/stats models, not markdown tables), set "unreasonable" goals and call them reasonable, adversarially challenge assumptions against raw data, and use an outside judge — never let the model grade itself.
  • Range — draw on multiple fields. "Replace nouns with verbs" (a QBR deck is "getting busy people to decide under uncertainty in 30 min"), then assemble a crew of disciplines — and ask the model to do what each expert does, not role-play writing like them. Shines with multi-agent/subagent setups (see Agents).

A reusable depth prompt he offers: "I want a deeper version of this task, not a bigger one. Before rewriting it: (1) what a top professional would do that I'm not asking for; (2) the rawest material they'd start from; (3) the specific methods/tools they'd use; (4) what, other than you or me, would show the result is right. Then rewrite my prompt to ask for exactly that." Full writeup in Reading.

Reasoning & continual learning

  • The "sleep" framework (continual learning). Google Research (Behrouz, Mirrokni et al.) proposes a biologically inspired "sleep" phase: a deployed LLM periodically consolidates short-term context into long-term parameters, then trains on self-generated "dream" data — keeping near-zero forgetting across sequential tasks (e.g. learning unseen languages like Manchu and Kalamang back-to-back) where in-context-learning and plain SFT baselines collapse. It attacks the static-knowledge-cutoff problem directly: a path toward agents that update from their own experience post-deployment instead of being frozen at a cutoff — relevant to durable agent memory (see Agents). (Google Research blog Oct 27; @GoogleResearch first-party announcement Oct 28)

Loop engineering (self-driving agent loops)

"Replace yourself as the person who prompts the agent — design the system that does it instead" (Addy Osmani, Loop Engineering). A loop is a recursive goal: define a purpose, the agent iterates until a condition holds. Key primitives, now in both Claude Code and Codex:

  • /loop — re-run on a cadence; /goal — keep going until a verifiable stopping condition is true.
  • The writer isn't the grader: after each turn a separate small model checks whether the goal is met — the same verifier-≠-generator discipline behind this repo's own RSI loop (docs/rsi-framework-generic.html) and the verification-as-bottleneck thread. Sits one floor above "harness engineering" (the single-agent environment).
  • Caveats (stated plainly): token cost varies wildly; quality/"slop" control still needs an explicit check — which is exactly why the verifiable stopping condition matters.
  • In practice (Practical Loop Engineering): compose /schedule (checks for work on a cadence) + /goal (deterministic done-condition, e.g. "Lighthouse ≥ 90, stop after 5 tries") + skills (how to verify) + dynamic workflows (orchestrate triage→fix→review) + auto mode (runs without asking). Prefer deterministic stop criteria (tests passed, score threshold) so the evaluator model isn't guessing "good enough."
